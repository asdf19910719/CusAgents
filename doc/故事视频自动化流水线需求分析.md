# 故事视频自动化流水线需求分析

更新时间：2026-05-08

## 1. 目标

建设一条从故事输入到分镜视频片段生成的全自动流水线：

1. 输入故事概要、故事大纲、世界观设定、角色设定等文本。
2. 由 AI 生成结构化故事分镜剧本。
3. 根据故事设定生成角色三视图、场景图、物品图等参考资产。
4. 根据分镜剧本和参考资产生成多个分镜图，或生成多宫格分镜图后切分为分镜图；此步骤可选。
5. 根据分镜剧本、分镜图、角色/场景/物品参考图生成视频。
6. 一个分镜视频生成完成后，系统自动继续生成下一个分镜视频。
7. 全程自动化，可恢复、可查询、可通知。
8. 第一版不做 UI，以 API、命令、后台任务和文档化输出为主；后续版本再做 UI 配置、输入和结果展示。

第一版目标不是直接生成完整成片，而是稳定生成“项目级分镜剧本 + 参考资产 + 分镜图 + 分镜视频片段清单”。后续再扩展字幕、配音、剪辑合成和剪映导出。

## 2. 当前已有能力

CusAgents 当前已具备以下基础：

- 故事概要生成、分镜生成和 prompt 组装能力。
- 多图片后端抽象，包括第三方 API、Codex CLI、ChatGPT Web、即梦 CLI 等方案。
- `dreamina_cli` 图片后端，支持通过即梦 CLI 生成图片。
- `dreamina_video_cli` 视频后端，已接入 `/videos` 视频任务链路。
- 视频默认模型为 `seedance2.0`。
- 视频长任务状态支持 `querying`、`submit_id`、恢复查询和 `POST /videos/{video_id}/refresh`。
- 视频完成或失败后支持自动通知。
- 已有 FastAPI、数据库模型、Worker、飞书命令、通知服务和运行时健康检查能力。

这些能力应继续复用，不建议第一版替换成第三方影视工作流项目。

## 3. 用户约束

### 3.1 视频必须使用参考图的规则

用户明确要求：

- 有分镜图，或有角色/场景/物品参考图，就必须走带图视频生成。
- 只要有图片参与当前分镜视频生成，就都要上传给视频生成后端。
- 生成视频时，prompt 中必须说明每个图片文件名及用途。

工程实现时，“image2video”应理解为业务层的“带图视频生成”统称，而不是强行调用即梦 CLI 的单图 `image2video` 命令。

### 3.2 即梦视频模式路由规则

根据即梦 CLI 能力，推荐路由如下：

1. `reference_images_count == 0`：使用 `text2video`。
2. `reference_images_count == 1`：使用 `image2video`。
3. `reference_images_count >= 2`：使用 `multimodal2video`。
4. `keyframe_sequence == true`：使用 `multiframe2video`。

如果图片数量超过即梦 `multimodal2video` 的上限，按优先级选择：

1. 当前分镜图。
2. 当前分镜出场主角参考图。
3. 当前场景参考图。
4. 当前分镜关键物品参考图。
5. 次要角色或辅助风格图。

被截断的图片需要记录在任务元数据中，便于排查生成一致性问题。

### 3.3 视频长任务规则

视频生成一般需要几十分钟或数小时，不应假设几分钟内完成。

系统必须：

- 提交后保存 `submit_id`。
- 对 `querying` 状态长期保留。
- 支持通过 `submit_id` 恢复查询。
- 不用同步 HTTP 请求阻塞等待视频完成。
- 视频完成后自动通知。
- 视频完成后自动调度下一个分镜视频。
- 服务重启后可以恢复未完成项目。

## 4. 开源影视工作流调研结论

已真实克隆并分析以下项目：

- `runtime/research/ArcReel`
- `runtime/research/OpenMontage`
- `runtime/research/ttv-pipeline`
- `runtime/research/openstory`
- `runtime/research/ViMax`

结论：不建议直接使用或合并克隆代码。推荐结构借鉴，保留 CusAgents 现有 FastAPI、数据库、Worker、即梦、ChatGPT Web、飞书通知等能力。

### 4.1 ArcReel

ArcReel 是最接近当前需求的完整影视项目产品，具备项目资产结构、分镜图、宫格图、参考视频、任务队列、视频后端、费用追踪和剪映导出等能力。

但第一版不建议直接引入 ArcReel 代码：

- ArcReel 是 AGPL-3.0，直接拷贝或深度合并代码会带来许可证约束。
- ArcReel 依赖 Claude Agent SDK，Windows 原生不友好。
- CusAgents 已经具备大量重叠能力，直接替换会浪费现有进度。

推荐借鉴：

- 项目级资产目录和数据模型。
- `storyboard`、`grid`、`reference_video` 三类模式。
- 任务队列与恢复机制。
- 视频后端能力抽象，包括 `start_image`、`end_image`、`reference_images`、`max_reference_images`。

需要注意：ArcReel 普通 `storyboard` 视频阶段主要上传分镜图作为 `start_image`；角色/场景/道具 sheet 直接参与视频生成主要在 `reference_video` 模式。CusAgents 当前需求应合并两者，即“分镜图 + 角色/场景/物品参考图都参与视频生成”。

### 4.2 TTV Pipeline

TTV Pipeline 适合参考长视频连续性策略：

- Keyframe Mode。
- Chaining Mode。
- 最后一帧接下一段。
- 长文本分段与视频片段串行生成。

第一版可借鉴“按分镜串行”和“尾帧/关键帧连续性”思路，但不直接引入代码。

### 4.3 ViMax

ViMax 适合参考算法与 prompt 设计：

- `ReferenceImageSelector`。
- `BestImageSelector`。
- 候选图一致性评分。
- 多机位镜头规划。
- 分镜/镜头 prompt 组织。

第一版可先保留简单优先级策略，后续再扩展一致性评分。

### 4.4 OpenMontage

OpenMontage 适合后期生产工具链参考：

- pipeline manifest。
- 工具注册表。
- 字幕、配音、音乐、合成。
- 成本和质量门。

第一版不把它作为主流程依赖，后续做成片合成时再评估。

### 4.5 OpenStory

OpenStory 适合参考 UI 和状态管理：

- sequence/frame/video 状态。
- 角色库、场景库、画面序列管理。
- Web SaaS 型交互。

第一版无 UI，后续 UI 阶段可参考。

## 6. 视频请求对象建议

当前 `VideoProvider.generate_video(prompt)` 后续应扩展为结构化请求对象：

```text
VideoGenerationRequest:
- prompt
- mode
- start_image
- end_image
- reference_images[]
- reference_image_usages[]
- duration
- ratio
- resolution
- model_version
- submit_id
```

字段含义：

- `prompt`：最终视频 prompt。
- `mode`：`text2video`、`image2video`、`multimodal2video`、`multiframe2video`。
- `start_image`：当前分镜图或首帧图。
- `end_image`：尾帧图，可用于连续性。
- `reference_images[]`：角色、场景、物品等参考图。
- `reference_image_usages[]`：每张图的文件名、类型、用途说明。
- `duration`：分镜时长。
- `ratio`：画幅比例。
- `resolution`：视频分辨率。
- `model_version`：默认 `seedance2.0`。
- `submit_id`：恢复查询用。

## 7. Prompt 组装规则

视频 prompt 必须包含：

- 当前分镜剧情。
- 镜头语言。
- 动作和情绪。
- 场景和光线。
- 参考图清单。
- 一致性约束。
- 禁止事项。

示例：

```text
分镜 001：
主角在雨夜小巷中缓慢回头，镜头从背后低角度推近，霓虹灯反射在积水上。

参考图清单：
- shot_001.png：当前分镜图，作为本镜头构图、角色站位、动作起点。
- character_hero_turnaround.png：主角三视图，保持脸型、发型、服装和体型一致。
- scene_alley.png：小巷场景参考，保持空间结构、光线和材质。
- prop_sword.png：长剑道具参考，保持外观一致。

视频要求：
请根据上述参考图生成本分镜视频。保持角色身份、服装、场景结构和关键道具外观一致。镜头运动要平稳，不要新增未出现的主要角色，不要改变主角服装颜色。
```

## 8. 第一版自动化流程

### 8.1 项目创建

输入：

- 故事概要或大纲。
- 世界观和风格设定。
- 可选角色设定。
- 可选场景设定。
- 可选物品设定。
- 可选画幅、时长、分镜数量、视频模型参数。

输出：

- `StoryProject`
- `StoryPipelineRun`

### 8.2 生成分镜剧本

由 AI 生成结构化分镜：

- 分镜序号。
- 画面描述。
- 剧情动作。
- 角色出场。
- 场景。
- 物品。
- 镜头语言。
- 预计时长。
- 参考资产需求。

### 8.3 生成参考资产

根据故事设定生成：

- 角色三视图。
- 场景图。
- 物品图。
- 可选风格图。

第一版推荐只生成每个关键对象的一张稳定参考图；角色可优先生成三视图。

### 8.4 可选生成分镜图

根据分镜剧本和参考资产生成：

- 每个分镜一张分镜图。
- 或多宫格分镜图，并切分为单分镜图。

该步骤可配置跳过。如果跳过，视频阶段仍使用角色/场景/物品参考图走带图视频生成。

### 8.5 按分镜生成视频

对每个 `StoryShot`：

1. 收集当前分镜图。
2. 收集当前分镜出场角色参考图。
3. 收集当前场景参考图。
4. 收集当前关键物品参考图。
5. 生成图片用途 manifest。
6. 组装视频 prompt。
7. 根据图片数量选择即梦视频模式。
8. 提交视频任务并保存 `submit_id`。
9. 如返回 `querying`，进入长任务等待。
10. 成功后保存视频资产并通知。
11. 自动提交下一个分镜视频。

### 8.6 项目完成

所有分镜视频完成后：

- 生成项目级视频片段清单。
- 标记 `StoryProject.completed`。
- 通知用户结果。
- 后续可扩展字幕、配音、合成和导出。

## 9. 恢复与调度

第一版推荐沿用现有 FastAPI + DB 状态机 + Worker，不引入新的重型编排框架。

需要新增项目级恢复调度：

- 定期扫描 `StoryProject.status = generating_videos`。
- 找到 `StoryShotVideoJob.status = querying` 的任务。
- 使用保存的 `submit_id` 调用恢复查询。
- 如果视频成功，写入视频资产并调度下一个分镜。
- 如果失败，记录失败原因并通知。
- 如果仍是 `querying`，保持状态，不刷屏通知。

后续如需要生产级长任务编排，可优先评估 Temporal。Prefect、Dagster、LangGraph、ComfyUI 更适合作局部参考，不建议第一版替换核心编排。

## 10. 第一版阶段拆分

### 阶段 1：需求与模型设计

- 固化本文档。
- 设计 `StoryProject`、`StoryReferenceAsset`、`StoryShot`、`StoryShotImage`、`StoryShotVideoJob`、`StoryPipelineRun`。
- 设计视频参考图 manifest 和 prompt 组装规则。

### 阶段 2：项目与分镜生成

- 新增故事项目创建 API 或命令。
- 接入 AI 生成结构化分镜剧本。
- 保存分镜到数据库。

### 阶段 3：参考资产生成

- 生成角色三视图、场景图、物品图。
- 资产入库并关联项目。
- 记录图片文件名和用途。

### 阶段 4：可选分镜图生成

- 支持逐分镜生成分镜图。
- 支持多宫格分镜图并切分。
- 支持跳过分镜图直接进入视频阶段。

### 阶段 5：视频编排器

- 实现参考图收集器。
- 实现视频模式选择器。
- 实现视频 prompt 图片清单构造器。
- 实现按分镜串行提交视频任务。
- 支持 `querying`、`submit_id`、恢复查询和完成后继续下一个分镜。

### 阶段 6：项目完成与后续扩展

- 生成项目级片段清单。
- 通知完成结果。
- 后续扩展字幕、配音、合成、剪映导出、UI 展示和人工调整。

## 11. 后续成熟影视工作流能力吸收方案

第一版完成“故事输入 -> 分镜剧本 -> 参考资产 -> 分镜图 -> 分镜视频片段”的自动化闭环后，可以逐步吸收成熟影视工作流中的 UI、质量门、合成和导出能力。推荐原则是：先把 CusAgents 自有流水线跑稳定，再按模块吸收，不直接替换核心系统。

### 11.1 UI 与项目工作台

参考来源：

- OpenStory：sequence/frame/video 状态、角色库、场景库、画面序列管理。
- ArcReel：项目资产结构、生成模式入口、任务队列展示、成本追踪。

推荐建设一个项目工作台：

- 项目总览：展示故事标题、当前阶段、总体进度、失败任务、待人工处理事项。
- 分镜列表：按顺序展示每个 `StoryShot` 的剧本文本、分镜图、视频状态、参考图清单和重试入口。
- 资产库：集中管理角色三视图、场景图、物品图、风格图，支持替换、锁定、禁用和重新生成。
- 视频任务面板：展示 `queued/running/querying/succeeded/failed`，保留 `submit_id`、模型、耗时、失败原因和恢复查询入口。
- 人工调整入口：允许用户编辑分镜 prompt、替换参考图、调整图片优先级、重新生成某个分镜，而不是重跑整个项目。

第一版 UI 不需要做复杂剪辑时间线，优先做“项目状态 + 资产管理 + 分镜任务控制台”。

### 11.2 质量门与一致性检查

参考来源：

- OpenMontage：成本/质量门、pipeline stage 校验。
- ViMax：参考图选择、候选图一致性评分、BestImageSelector。
- ArcReel：生成任务状态、资产检查、费用追踪。

推荐分三层质量门：

1. 输入质量门：检查故事设定是否足够生成分镜，角色/场景/物品是否命名清晰，缺少关键设定时由 AI 补全并记录假设。
2. 图片质量门：检查角色三视图、场景图、物品图、分镜图是否生成成功，是否存在明显空图、失败图、尺寸异常或路径缺失。
3. 视频质量门：检查视频是否成功落盘、时长是否符合预期、是否有关联分镜、是否保留 `submit_id` 和参考图 manifest。

后续增强项：

- 一致性评分：用视觉模型或多模态模型比较角色参考图、分镜图和视频首帧，给出角色服装、脸型、场景一致性评分。
- 自动重试策略：低于阈值的图片或视频自动重试一次，并在 prompt 中强化失败点。
- 人工审核队列：无法自动判定的任务进入 `needs_review` 状态，由 UI 提供接受、重试、替换参考图等操作。
- 成本门控：在重试或批量生成前估算消耗，超过预算时暂停并通知。

第一版后续落地优先级建议：先做文件/状态/manifest 的硬校验，再做视觉一致性评分。

### 11.3 成片合成能力

参考来源：

- OpenMontage：Remotion/FFmpeg 合成、字幕、配音、音乐、pipeline manifest。
- TTV Pipeline：长视频分段、片段串接、最后一帧接下一段。
- ArcReel：剪映导出和项目级片段组织。

推荐后续新增 `StoryComposition` 模块：

- 输入：已完成的分镜视频片段清单、分镜剧本、字幕文本、配音配置、音乐配置。
- 输出：合成后的视频文件、字幕文件、剪辑工程文件或导出包。
- 核心能力：按分镜顺序拼接视频，生成字幕时间轴，叠加配音和背景音乐，处理转场、片头、片尾、水印和安全边距。

第一阶段合成可只做 FFmpeg 串接：

- 按 `shot_index` 排序所有成功视频。
- 校验分辨率、比例、编码参数。
- 生成 `concat` 清单。
- 输出一个粗剪视频。

第二阶段再做增强：

- 字幕：根据分镜剧本或旁白生成 SRT/ASS。
- 配音：接入 TTS，把旁白按分镜生成音频。
- 音乐：支持项目级背景音乐或按场景切换。
- 转场：支持硬切、淡入淡出、黑场、简单推拉。
- 片头片尾：根据项目标题和作者信息自动生成。

如果后续需要更强的模板化视觉包装，可评估 Remotion；如果只需要稳定批处理，FFmpeg 优先。

### 11.4 导出能力

参考来源：

- ArcReel：剪映导出、项目资产目录。
- OpenMontage：pipeline 输出包、素材组织。

推荐导出类型：

- 片段清单导出：JSON，包含每个分镜的视频路径、参考图、prompt、模型、`submit_id`、状态和耗时。
- 素材包导出：按项目打包故事剧本、分镜剧本、角色/场景/物品参考图、分镜图、视频片段。
- 粗剪视频导出：输出一个 MP4 粗剪文件。
- 字幕导出：输出 SRT/ASS。
- 剪辑工程导出：后续评估剪映、Premiere、DaVinci Resolve 或通用 EDL/XML。

第一版后续建议优先支持“片段清单 JSON + 素材包导出”，因为它对自动化调试和人工剪辑最有价值，成本也最低。

### 11.5 后续阶段建议

建议把成熟影视工作流能力拆成四个后续阶段：

1. 后续阶段 A：项目工作台 UI。目标是让用户可视化查看项目、资产、分镜和任务状态。
2. 后续阶段 B：质量门。目标是把失败、缺图、路径错误、低一致性和高成本风险前置暴露。
3. 后续阶段 C：合成。目标是把分镜视频片段合成为粗剪视频，并支持字幕和配音。
4. 后续阶段 D：导出。目标是输出素材包、粗剪视频、字幕和剪辑工程文件。

推荐实施顺序：UI 工作台和质量门优先，其次是素材包导出，再做 FFmpeg 粗剪合成，最后再做剪辑工程导出和高级后期能力。

## 12. 非目标

第一版暂不做：

- 完整 Web UI。
- 完整成片剪辑合成。
- 配音、字幕、音乐。
- 多供应商自动成本优化。
- ArcReel、OpenStory 等项目代码直接合并。
- 对视频生成速度做强承诺。

## 13. 风险与待确认

- 即梦 `multimodal2video` 的图片数量上限需要在实现时通过 CLI help 或真实调用确认。
- 多张参考图可能不一定都被模型有效遵循，需要后续引入一致性评分或人工复核。
- 视频长任务耗时取决于 Dreamina 外部队列，系统只能保证可恢复和自动继续。
- 角色三视图生成质量会影响后续分镜图和视频一致性。
- 后续如果要直接使用 ArcReel 代码，需要重新评估 AGPL-3.0 许可证影响。

## 14. 当前推荐结论

推荐第一版采用“CusAgents 自研轻量影视流水线 + ArcReel/TTV/ViMax/OpenMontage/OpenStory 结构借鉴”的方案。

核心理由：

- 最大化复用当前已完成的即梦 CLI、ChatGPT Web、视频长任务、通知和飞书命令能力。
- 避免 AGPL-3.0 和跨技术栈迁移成本。
- 优先解决用户最关键闭环：故事输入、分镜、参考图、分镜图、逐分镜视频生成、长任务恢复和自动继续。
- 后续仍可逐步吸收成熟影视工作流的 UI、质量门、合成和导出能力。
