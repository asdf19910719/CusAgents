# 影视类开源工作流调研

更新时间：2026-05-08

本轮已真实克隆并核对以下仓库：

- `runtime/research/ArcReel`
- `runtime/research/OpenMontage`
- `runtime/research/ttv-pipeline`
- `runtime/research/openstory`
- `runtime/research/ViMax`

## 结论

已经存在较成熟的影视类/视频类 AI 工作流项目，但它们各自侧重点不同。对 CusAgents 当前需求来说，最有价值的不是直接替换，而是组合借鉴：

1. **主参考：ArcReel**
   - 它是最接近“故事/小说 -> 角色/场景/道具 -> 分镜图/宫格图 -> 视频片段 -> 成片”的完整产品。
   - 它有 FastAPI 后端、React UI、项目资产结构、生成任务队列、图片/视频/文本多供应商后端、费用追踪、剪映导出、Agent runtime。
   - 它真实支持三种生成模式：`storyboard`、`grid`、`reference_video`。
   - 普通 `storyboard` 视频阶段主要上传分镜图作为 `start_image`；角色/场景/道具 sheet 更多用于生成分镜图。
   - `reference_video` 模式会直接把角色/场景/道具 sheet 作为视频参考图上传，并把 prompt 中的 `@名称` 转成 `[图N]`。
   - 这说明 CusAgents 的需求比 ArcReel 的普通 `storyboard` 模式更强：我们需要“分镜图 + 角色/场景/物品参考图一起参与视频生成”，更接近 ArcReel 的 `storyboard` 与 `reference_video` 合并版。

2. **次参考：OpenStory**
   - 它是脚本到视频序列平台，技术栈是 Bun + TanStack Start + Drizzle + QStash Workflow + Cloudflare/R2。
   - 它的 UI、scene/frame/video 状态、角色库、画面序列管理值得参考。
   - 它偏 Web SaaS/Edge 架构，不适合直接合并到 CusAgents 的 Python/FastAPI 栈。

3. **长视频连续性参考：TTV Pipeline**
   - 它专门解决长文本到长视频：分段、关键帧、首尾帧、最后一帧接下一段、并行/串行策略、远程 API fallback。
   - 对 CusAgents 最有价值的是 `Keyframe Mode` 与 `Chaining Mode`：前者适合多关键帧并行，后者适合视频片段串行连续。
   - 它不负责角色/场景/道具资产库，不是完整影视项目系统。

4. **生产工具链参考：OpenMontage**
   - 它不是剧情分镜资产库型项目，而是“Agent + YAML pipeline + 工具注册表 + Remotion/FFmpeg/素材库”的通用视频生产系统。
   - 强项是 pipeline manifest、stage director skill、工具选择、成本/质量门、字幕/配音/音乐/合成。
   - 适合后续参考“成片合成、字幕、配音、质量门、预算治理”，不适合替代当前故事视频生成主线。

5. **算法/多 Agent 参考：ViMax**
   - 它是多 Agent 视频生成框架，包含 Idea2Video、Script2Video、StoryboardArtist、ReferenceImageSelector、BestImageSelector、CameraImageGenerator。
   - 它对“参考图选择、候选图一致性评分、多机位镜头规划、第一帧/尾帧视频生成”非常有借鉴价值。
   - 工程产品化程度弱于 ArcReel/OpenStory，更适合作为算法与 prompt 设计参考。

## ArcReel 的关键可借鉴设计

### 1. 三种生成模式

ArcReel 在 `agent_runtime_profile/CLAUDE.md` 中定义：

- `storyboard`：分镜图生视频。数据主结构是 `segments[]` 或 `scenes[]`，视觉参考来源是每片段一张分镜图。
- `grid`：宫格生视频。先生成宫格图，切块后作为分镜图。
- `reference_video`：参考生视频。数据主结构是 `video_units[]`，视觉参考来源是角色/场景/道具 sheet 图。

CusAgents 推荐采用类似模式，但把视频阶段路由改得更强：

- 有分镜图：分镜图作为当前镜头首帧/构图参考。
- 有角色/场景/物品参考图：也必须一起上传给视频模型。
- 如果图片超过即梦 `multimodal2video` 上限，需要按优先级选择：分镜图 > 出场主角 > 当前场景 > 关键物品 > 次要角色。

### 2. 视频后端能力抽象

ArcReel 的 `lib/video_backends/base.py` 有：

- `start_image`
- `end_image`
- `reference_images`
- `VideoCapabilities.last_frame`
- `VideoCapabilities.reference_images`
- `VideoCapabilities.max_reference_images`

CusAgents 后续也应把当前 `VideoProvider.generate_video(prompt)` 扩展为请求对象：

```text
VideoGenerationRequest:
- prompt
- mode
- start_image
- end_image
- reference_images[]
- reference_image_usages[]
- duration
- ratio
- resolution
- model_version
- submit_id
```

### 3. Ark/Seedance 图片角色上传方式

ArcReel 的 Ark 后端会把图片转成 base64 data URI，并在 content 中标注：

- `role=first_frame`
- `role=last_frame`
- `role=reference_image`

CusAgents 使用即梦 CLI，不一定能直接用 role 字段，但应在内部模型里保留类似语义，映射到 CLI 时：

- 单图：`image2video --image <path>`
- 多图：`multimodal2video --image <path1> --image <path2> ...`
- 多关键帧：`multiframe2video --images <path1> <path2> ...`

### 4. `reference_video` 的 prompt 映射

ArcReel 的参考视频模式做了两件事：

- 剧本里用 `@角色名/@场景名/@道具名` 指代参考对象。
- 执行时按 references 顺序把 `@名称` 转成 `[图N]`，确保 prompt 和上传图片顺序一致。

CusAgents 推荐更明确一点：直接在 prompt 中写文件名和用途。

示例：

```text
参考图清单：
- shot_001.png：当前分镜图，作为本镜头构图、角色站位、动作起点。
- character_hero_front.png：主角三视图，保持脸型、发型、服装一致。
- scene_alley.png：小巷场景参考，保持空间结构、光线和材质。
- prop_sword.png：长剑道具参考，保持外观一致。

视频要求：
请根据上述参考图生成本分镜视频，不要改变角色身份、服装、场景结构和关键道具外观。
```

### 5. 任务队列和恢复

ArcReel 使用 SQLAlchemy 任务表和 lease-based worker：

- `queued/running/succeeded/failed/cancelled`
- image/video 独立并发通道
- provider 维度并发池
- running task 回收
- checkpoint 支持 `--resume`

CusAgents 当前已有 `VideoJob.querying/submit_id/refresh`，应继续沿用，不必完全复制 ArcReel 的队列。但需要新增项目级恢复调度：

- 扫描 `StoryProject.status in running`
- 找到 `ShotVideoJob.status=querying`
- 用 `submit_id` 刷新
- 成功后写入视频资产
- 自动提交下一个分镜

## 对当前 CusAgents 的设计修正

### 视频模式选择规则

用户规则：“有分镜图或有角色/场景参考图，就使用 image2video；只要有图片都要上传；生成视频 prompt 中说明图片名称是参考图。”

工程实现应按即梦 CLI 能力细化为：

1. `reference_images_count == 0`：`text2video`
2. `reference_images_count == 1`：`image2video`
3. `reference_images_count >= 2`：`multimodal2video`
4. `keyframe_sequence == true`：`multiframe2video`

这里的“image2video”是业务上的“带图视频”统称；代码里不应强行把多图塞进单图 `image2video`。

### 第一版项目结构

建议新增：

- `StoryProject`：故事项目。
- `StoryReferenceAsset`：角色/场景/物品/风格参考图。
- `StoryShot`：分镜。
- `StoryShotImage`：分镜图/宫格切块图。
- `StoryShotVideoJob`：单分镜视频任务。
- `StoryPipelineRun`：一次自动化运行记录。

### 第一版自动化流程

1. 输入故事概要/大纲/设定。
2. LLM 生成结构化分镜剧本。
3. 提取角色、场景、物品，生成参考图。
4. 可选生成分镜图或多宫格分镜图。
5. 对每个分镜收集图片：分镜图、角色图、场景图、物品图。
6. 根据图片数量选择 `text2video/image2video/multimodal2video/multiframe2video`。
7. prompt 自动注入图片文件名和用途映射。
8. 提交视频任务后保存 `submit_id`。
9. 若 `querying`，进入长任务等待；不阻塞整个请求。
10. 完成后通知并自动调度下一个分镜。
11. 所有分镜完成后生成项目级片段清单，后续再做合成/剪映导出。

## 推荐实施取舍

第一版不建议直接引入 ArcReel 代码，原因：

- ArcReel 是 AGPL-3.0，直接代码合并会带来许可证约束。
- ArcReel 依赖 Claude Agent SDK，Windows 原生不友好，推荐 WSL2/Docker。
- CusAgents 已经有即梦 CLI、ChatGPT Web、飞书命令、通知、视频长任务恢复等能力，直接替换会浪费现有进度。

推荐做法：

- 数据结构和流程参考 ArcReel。
- 连续性策略参考 TTV Pipeline。
- 参考图选择与一致性评分参考 ViMax。
- 后期合成、字幕、配音、质量门参考 OpenMontage。
- UI/sequence 状态参考 OpenStory。
