# 当前系统详细使用说明

## 1. 系统定位

当前项目已经不是单纯的内容生成后端，而是一个可通过飞书远程控制的本机 Agents 系统。

它现在支持两类能力：

1. 预定义工作流
   例如故事生成、分镜、Prompt 组装、出图、质量检查、结果回传。
2. 自然语言 Codex 远程执行
   你在飞书里发送普通文本，系统会默认把它当成一条 `codex exec` 任务执行。

当前推荐理解方式：

1. 普通文本 = 交给 Codex CLI
2. `/create` = 触发你定义好的出图工作流
3. `/status`、`/retry`、`/approve`、`/cancel`、`/assets`、`/health`、`/codex_status` = 显式控制命令

## 2. 当前已完成能力

### 2.1 飞书控制层

当前已支持：

1. 飞书长连接接收消息
2. 飞书 webhook 接收消息
3. 飞书命令执行结果文本回发
4. 飞书图片上传与图片消息回发
5. 飞书命令审计日志
6. 飞书重放保护

### 2.2 工作流能力

当前已支持：

1. 任务创建
2. 大纲生成
3. 分镜生成
4. Prompt 组装
5. 多后端出图
6. 质量检查
7. 等待审核
8. 审核通过/重试/取消

### 2.3 出图后端

当前支持四个后端：

1. `comfyui_remote`
   适合远程台式机或本机 GPU 跑 ComfyUI。
2. `third_party`
   适合接第三方图像 API。
3. `codex_cli`
   适合本机已登录 Codex CLI 的实验型出图。
4. `chatgpt_web`
   适合复用独立 Playwright 登录态，在 ChatGPT 网页里模拟人工生图的半自动方案。

当前最稳的后端建议：

1. 先用 `codex_cli` 跑通
2. 再逐步切到 `comfyui_remote`
3. `third_party` 仅作为补充或兜底
4. `chatgpt_web` 适合你已有 ChatGPT 网页能力、但暂时不想接第三方图片 API 的场景

## 6. 飞书里的使用方式

## 6.1 普通文本

飞书里发送不以 `/` 开头的普通文本时，系统会默认将整段文本作为一条 `codex exec` prompt。

示例：

```text
帮我检查一下当前仓库里最容易出问题的三个模块，并各给一句原因
```

```text
读取 README，并总结当前已知限制
```

```text
帮我在这个项目里定位与飞书消息回发相关的核心文件
```

这类消息的执行路径是：

1. 飞书消息进入系统
2. 解析为 `run_codex`
3. 命中当前 `chat_id` 的正式会话
4. 把当前用户消息写入会话
5. 结合会话摘要和最近消息生成本次执行 prompt
6. 创建 `CodexRun`
7. 入队
8. Worker 调用 `codex exec`
9. 文本结果写回同一会话并回发到原飞书会话
10. 如果产生图片，也尝试回发图片

## 6.2 显式 Codex 命令

如果你仍然想显式写命令，也支持：

```text
/codex prompt="Inspect this repo and reply with exactly one line: OK"
```

或者：

```text
/codex Read README and summarize blockers
```

查询状态：

```text
/codex_status run=12
```

手动重置会话：

```text
/new
```

说明：
1. `/new` 会关闭当前 `chat_id` 的活跃会话并立即创建一条新会话
2. `/new` 自身不进入会话历史

## 6.3 工作流命令

工作流类任务建议继续使用显式命令。

创建任务：

```text
/create topic="极简红色方块练习图" style=minimal shots=1 backend=codex_cli
```

再例如：

```text
/create topic="赛博武侠雨夜街头决战" style=cinematic shots=3 backend=comfyui_remote
```

参数说明：

1. `topic`
   题材或任务主题。
2. `style`
   风格预设，例如 `minimal`、`cinematic`。
3. `shots`
   目标镜头数。
4. `backend`
   出图后端，可选：
   - `codex_cli`
   - `comfyui_remote`
   - `third_party`
   - `chatgpt_web`

## 6.5 Codex 正式会话规则

当前 Codex 会话已经不是“完全无历史的单次执行”，而是按 `chat_id` 共享的正式会话层：

1. 只有普通文本和 `/codex` 会进入会话
2. `/create`、`/status`、`/retry`、`/approve`、`/cancel`、`/assets`、`/health`、`/codex_status` 不进入会话
3. 会话空闲超过 `CONVERSATION_IDLE_TIMEOUT_SECONDS` 后，下一条普通文本或 `/codex` 会自动开启新会话
4. 会话过长时，系统会把旧消息压成摘要，并保留最近若干条原文
5. 当前实现的是“正式会话模型 + 上下文组装”，不是底层原生 CLI session 复用

## 7. 图片回传说明

当前图片回传已经支持：

1. 工作流完成后，把首个生成素材回发到飞书
2. Codex 任务如果产出图片，也尝试回发图片

前提条件：

1. `FEISHU_APP_ID` 已配置
2. `FEISHU_APP_SECRET` 已配置
3. 飞书应用消息接口可用

当前图片回传不是发本地路径，而是：

1. 先把本地图片上传到飞书
2. 获取 `image_key`
3. 再发送飞书 `image` 消息

所以飞书里能直接看到图片，而不是仅看到本机文件路径。

## 11. 当前推荐使用方案

如果你是日常使用，推荐顺序如下：

1. API 启动
2. Worker 启动
3. 飞书长连接启动
4. 飞书先发 `/health`
5. 然后：
   - 普通文字测试 Codex 自然语言能力
   - `/create ... backend=codex_cli` 测工作流

推荐初始组合：

1. 文本推理：使用已配置 LLM
2. 工作流出图：优先 `codex_cli`
3. 远程高质量出图：逐步切到 `comfyui_remote`
4. 网页半自动生图：需要时切到 `chatgpt_web`

## 12. 当前边界与注意事项

1. 普通文本默认会触发 Codex 任务，不适合把飞书当纯聊天窗口随便发闲聊。
2. 当前“自然语言远程终端”本质上是任意 `codex exec` prompt，不是任意原生 shell。
3. 如果未来要开放真正的 shell 级终端，需要再加专门的高风险执行通道。
4. `third_party` 图像后端当前可能受上游稳定性影响。
5. `codex_cli` 更适合当前环境下的稳定实验与半生产使用。
6. `comfyui_remote` 更适合作为后续正式主出图后端。
7. `chatgpt_web` 属于“半自动稳定版”，不依赖第三方图像 API，但依赖 ChatGPT 网页 DOM 和下载链路稳定。

## 即梦 CLI 图片与视频

当前系统已新增两个即梦后端：

1. `dreamina_cli`：图片后端，接入现有 `/jobs` 工作流。
2. `dreamina_video_cli`：独立视频后端，接入 `/videos` 视频任务链路，默认模型为 `seedance2.0`。

图片任务示例：

```text
/create topic="赛博武侠雨夜决战" style=cinematic shots=1 backend=dreamina_cli
```

视频任务示例：

```text
/video prompt="cinematic slow push-in shot of a futuristic city at sunrise" duration=4 ratio=16:9 model=seedance2.0
```

API 示例：

```bash
curl -X POST http://127.0.0.1:8000/videos ^
  -H "Content-Type: application/json" ^
  -d "{\"prompt\":\"cinematic city sunrise\",\"duration\":4,\"ratio\":\"16:9\",\"video_resolution\":\"720p\",\"model_version\":\"seedance2.0\",\"backend\":\"dreamina_video_cli\"}"
```

视频生成通常是长任务，可能需要几十分钟甚至更久。`querying` 表示仍在即梦队列中，不应按失败处理；系统会保留 `submit_id`，可恢复查询：

```bash
curl -X POST http://127.0.0.1:8000/videos/{video_id}/refresh
C:\Users\91799\bin\dreamina.exe query_result --submit_id=<submit_id> --download_dir=./output/dreamina/videos
```

注意：即梦图片和视频都会消耗账号额度，视频消耗通常更高；默认配置不自动重试，避免失败时重复扣费。真实验收前先运行 `dreamina.exe user_credit`。

## 故事视频自动化流水线

当前系统已新增第一版无 UI 故事视频后端闭环：

1. 创建故事视频项目。
2. 保存角色/场景/物品参考图。
3. 保存结构化分镜。
4. 可保存分镜图。
5. 按分镜生成视频任务。
6. 有参考图时自动走带图视频模式。
7. 视频完成后可自动推进下一个分镜。

创建项目示例：

```bash
curl -X POST http://127.0.0.1:8000/story-videos/projects ^
  -H "Content-Type: application/json" ^
  -d "{\"title\":\"雨夜剑客\",\"source_text\":\"一个剑客在雨夜寻找真相\",\"source_type\":\"outline\",\"style_prompt\":\"cinematic noir\",\"reference_assets\":[{\"asset_type\":\"character_turnaround\",\"name\":\"hero\",\"description\":\"黑衣剑客三视图\",\"prompt\":\"hero turnaround\",\"file_path\":\"output/hero.png\"},{\"asset_type\":\"scene\",\"name\":\"alley\",\"description\":\"雨夜小巷\",\"prompt\":\"rain alley\",\"file_path\":\"output/alley.png\"}],\"shots\":[{\"shot_index\":1,\"title\":\"雨夜回头\",\"script_text\":\"主角在雨夜小巷中回头。\",\"visual_description\":\"霓虹灯反射在积水上。\",\"camera_motion\":\"低角度缓慢推近。\",\"character_names\":[\"hero\"],\"scene_names\":[\"alley\"],\"prop_names\":[],\"duration\":5,\"ratio\":\"16:9\",\"shot_image_path\":\"output/shot-001.png\"}]}"
```

提交下一个分镜视频：

```bash
curl -X POST http://127.0.0.1:8000/story-videos/projects/{project_id}/videos/next
```

恢复推进：

```bash
curl -X POST http://127.0.0.1:8000/story-videos/projects/{project_id}/resume
```

如果底层视频任务通过 `/videos/{video_id}/refresh` 查询到成功，并且该视频属于故事分镜，系统会标记当前分镜完成并继续提交下一个待生成分镜。

视频模式选择规则：

1. 无参考图：`text2video`。
2. 1 张参考图：`image2video`。
3. 2 张及以上参考图：`multimodal2video`。
4. 关键帧序列：`multiframe2video`。

生成视频时，系统会把参考图文件名和用途写入 prompt，并把同样的信息保存在 `reference_manifest_json` 中。
